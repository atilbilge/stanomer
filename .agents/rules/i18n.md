# ZERO STATIC TEXT & 100% INTERNATIONALIZATION (i18n) RULE

## 1. Absolute Prohibition of Hardcoded Strings (Statik Metin Kesinlikle Yasaktır)
- NEVER insert raw, hardcoded user-facing strings in TypeScript, TSX, JSX, or Dart files.
- Every user-facing label, button, modal text, banner, tooltip, validation error, validation warning, or placeholder MUST be retrieved via the translation system:
  - **Website / Next.js:** Use `t("translation_key")` backed by `website/lib/translations.json`.
  - **Flutter / Dart:** Use `AppLocalizations.of(context)` / `l10n`.

## 2. All 5 Languages Must Be Kept in Sync (5 Dil Eşzamanlı Güncellenir)
Whenever a new translation key is introduced or an existing key is modified in `website/lib/translations.json`, all 5 supported languages MUST be updated simultaneously:
1. `TR` (Turkish)
2. `EN` (English)
3. `SR_LAT` (Serbian Latin - Primary Market)
4. `SR_CYR` (Serbian Cyrillic)
5. `RU` (Russian)

Never leave any of the 5 languages missing or empty.

## 3. Validators, Helpers, and Services Return Keys Only
- Validation modules (e.g. `portalValidators.ts`), API responses, and backend helpers must NEVER return raw localized sentences.
- They must return structured issue objects with translation keys:
  ```ts
  { key: "agency_val_price_required", defaultText: "Cena mora biti veća od 0." }
  ```
- The UI layer is solely responsible for resolving the key using `t(err.key) || err.defaultText`.

## 4. Market Awareness
- Stanomer's primary operating market is Serbia.
- Agencies, landlords, and tenants predominantly use Serbian (`SR_LAT`) and English (`EN`).
- Hardcoding Turkish or any language directly into codebase files damages client experience and breaks language switching.
